# 对外视图过滤

> 交付前最后一遍减法：把只有内部才需要看的内容清掉，只留读者该看到的部分。

## 这个技能解决什么

写作是把过程和成品混在一起的过程。改了几版、哪条被评审质疑过、哪个数字还是暂定的——这些对写的人有用，对读的人全是噪音。文档交到评委手上，他看到的可能是“我们改过主意”，而不是“这个方案是什么”。

页面也一样。PPT 是拿去讲的，可页面上常常印着讲者准备说的整段台词、听众根本不会带走的口号、谁都懂的铺垫。

这个技能在定稿前跑一遍，把这两类东西清掉。它只做减法：不动事实、不动数字、不动结论。

## 它清什么

读者层（内容）：

- 稿件版本史、评审编号、给作者自己留的待办
- 元叙述：主语是“本页 / 本节 / 本稿”的自指句，以及对内容做解释、评价、纠偏的态度句
- 讲稿误入：页面上印着讲者要口述的段落、演示口令、导航提示
- 调试残留：`console.log`、TODO、调试面板与未完成功能入口
- 自加的说明性栏目、重复的边界声明、章末要点复述

表达层（语言）：

- 排版统一：中文引号一律全角弯引号，直角引号 `「」` `『』` 改成 `“”`
- 口语识别：只标记不替换，先定场合再定阈值
- 说清楚：不造压缩词、歧义词写清主体与客体、中文里非专业名词不用英文

## 三轮减法

| 轮次 | 抓什么 | 怎么抓 |
|---|---|---|
| 第一轮 | 已知痕迹 | 四条判据 + 文档 / 前端两张清单 |
| 第二轮 | 清单之外的冗余 | 按块过意图，逐条过角色 / 载体 / 增量三道测试 |
| 第三轮 | 位置没错但没必要的话 | 按载体定档，只对“有人讲”的载体做极致减法 |

第三轮的阈值随载体走：没人讲的文档要求信息自足，来龙去脉都在；有人讲的页面只留听众要带走的，能被口述的一律不上版面。

## 效果示例

内部工作稿里的一句话：

> 关于“原理独特性”的立场：v02 稿曾把“认知效能可观测化”列为原理层面的创新。经复核，这一表述超出了本稿能够支撑的范围……v03 将该要素下调为设计要素。

过完之后：

> 本方案的创新点按上表四项申领。认知效能可观测化列为设计要素，不申领原理层面的创新：其方法效度尚未标定（3.2、3.3），不足以支撑原理级主张。

评委读到的从“我们改过主意”变成“这条边界在哪”。方案立场保住了，改稿过程消失了。

## 怎么用

1. 把 `SKILL.md` 放进 agent 的技能目录。支持技能机制的 agent 都能用，除了 frontmatter 和 `SKILL.md`，其余文件都是可选资源。
2. 交付前，让 agent 按这个技能过一遍文档或页面。
3. 想先跑一遍机器检查，用配套脚本：

```bash
python scripts/scan_internal_traces.py <文件或目录>
python scripts/scan_colloquial.py <文件或目录> --register ppt
```

脚本只覆盖第一轮的已知痕迹，给出文件、行号、类别和原文片段；第二、三轮的判断由 agent 按技能里的判据做。

## 触发方式

跟 agent 说“对外交付前过一遍”“定稿前检查一下”“把内部痕迹清掉”“这页 PPT 帮我去掉讲稿”，都会命中这个技能。典型场景：交给评委或客户的报告与方案、授课与路演页面、要发布的前端页面。

## 适用与边界

- 适用于报告、方案、申报材料、授课与路演页面、前端交付物
- 不适用于写作过程中（会丢掉工作记忆），也不适用于内部工作稿和会话记录
- 它不替代去 AI 味：语言润色交给专门的中文润色技能，本技能只管“这句该不该出现在给这个读者的版本里”
