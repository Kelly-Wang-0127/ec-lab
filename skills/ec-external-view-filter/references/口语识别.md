# 口语识别与降档

表达层的一个子关：把“像说话、不像写文章”的地方标出来，按场合决定动不动。

它和第三轮“去语气”不是一回事，分工如下：

| | 第三轮·去语气 | 本关·口语识别 |
|---|---|---|
| 层面 | 结构层：一整句该留、该删、还是降级成补充 | 表达层：这句话的正式度够不够 |
| 动作 | 删 / 降级 / 留，改的是句子在页面上的**位置与形态** | 标记 + 给改写方向，**不动结构** |
| 适用 | 只对讲伴型（有人讲的载体） | 所有载体，含独读型文档 |
| 例子 | “它把注意力从反刍里拽回当下”→ 压成“作用　中断反刍” | “其实呢”“挺重要”→ 标出来，换中性说法 |

顺序：先走读者层三轮（该删的先删掉），最后再走这一关——删剩的才值得润。

## 为什么不做一对一词表

口语感大多不在词上，在句式上。两个反例：

- `关键不是比例，是呼气比吸气长` —— 一个口语词都没有，整句却是口语的“解释腔”
- `它把注意力从反刍里拽回当下` —— 没有语气词，但主语是“它”、动词是“拽”，是说话人的姿态

一对一替换表对这两句无从下手；硬套还会把好句子改坏。所以这里只做**识别**：认出特征、标出位置、说明理由，改不改交给人。

## 两层怎么分工

| 层 | 谁做 | 抓什么 | 输出 |
|---|---|---|---|
| 正则层 | `scripts/scan_colloquial.py` | 有固定形态的特征：语气词、叠词、口语句式、口语动词与量词 | 文件 + 行号 + 类别 + 置信档 |
| LLM 层 | 加载本技能的 agent | 句式型口语：解释腔、经验断言、主语姿态、口播感 | 段号 + 正式档 + 问题 + 改写方向 |

两层都跑完才算过完这一关。只跑脚本会漏掉**没见过的句式变体**（正则只认已知模板）；只靠 LLM 会漏掉零散的“呗”“啦”。

## 正则层：九类特征

脚本按置信分三档，口径是：

- **高** —— 形态本身即口语，书面语基本不出现（`呗/啵/咯`、`贼/超`、`搞定/折腾`、`一堆/点儿`、`反正/话说回来`）
- **中** —— 书面也能用，但用在这里偏口语（`吧/嘛/啊/呢/哦`、人称代词作主语、`挺/特别`、`把…给…`、`要是`、`其实/然后/就是说`）
- **低** —— 只是提示，可能是正当用法（`一…就…`、`什么…都`、比喻拟人）

```bash
python scripts/scan_colloquial.py <文件或目录>                    # 文本报告
python scripts/scan_colloquial.py <文件或目录> --format json      # 给 LLM 层读
python scripts/scan_colloquial.py <文件或目录> --register ppt     # 讲伴型：中档也当问题
python scripts/scan_colloquial.py <文件或目录> --min-level mid    # 只看中档以上
```

## 场合阈值（同一个词，不同载体不同结论）

| 载体 | 高置信 | 中置信 | 低置信 |
|---|---|---|---|
| 独读型文档（报告 / 方案 / 申报材料） | 改 | 正文改；引语、术语、患者原话可留 | 留 |
| 讲伴型 PPT 页面 | 改 | 改 | 看：影响版面观感就改 |
| 工作稿 / 会议纪要 / 内部备忘 | 留 | 留 | 留 |
| 文学、访谈、科普演讲稿 | 看体裁 | 看体裁，口语是人设的一部分 | 留 |

**先定场合再判，不要见到口语词就动。** 同一句“挺好的”，印在答辩页上要改，写进访谈记录里必须留。

## LLM 层：怎么判一段的正式档

### 输入

1. 原始文档
2. 脚本输出的 JSON（`--format json`）——作为**线索**，不是结论

### 三步

1. **切段**：按自然段 / 页面 / 板块切开，一段一段来，不跳段
2. **逐段过三测**

| 测试 | 怎么问 | 命中说明 |
|---|---|---|
| 人称测试 | 这段有没有“说话人”在场（我 / 你 / 咱们 / 大家） | 有 → 偏口语 |
| 解释测试 | 这段是在陈述事实，还是在解释、评价、纠偏、劝导 | 后者 → 偏口语（就是元叙述·态度型） |
| 口播测试 | 这段是**念出来才顺**，还是**读着就成立** | 念出来才顺 → 偏口语 |

口播测试是最灵的一条，一句就能辨：`关键不是比例，是呼气比吸气长`——默读别扭，念出来顺，就是口播句。

3. **定档并给方向**

| 档 | 特征 | 处理 |
|---|---|---|
| 书面硬 | 无人称、陈述句、术语准确、读着就成立 | 不动 |
| 中性 | 有轻微口语痕迹，但不影响阅读 | 看场合，可留 |
| 偏口语 | 三测命中两道以上 | 给改写方向 |

### 输出（三样）

1. **段位清单**：段号 / 档 / 命中哪一测 / 问题原句
2. **改写方向**：写“往哪走”，**不写定案**——例如“去掉解释腔，改直接陈述”而不是直接给新句子。定案由作者拍，因为改法往往不止一种
3. **待确认**：拿不准的（引语？术语？体裁需要？）单列，不擅自动

## 提示词模板（给 agent 用）

```
按 references/口语识别.md 的 LLM 层走一遍。

输入：<文档路径> + <脚本 JSON 输出>
场合：<独读型 / 讲伴型 / 混合型>，读者是 <谁>

要求：
1. 逐段过三测（人称 / 解释 / 口播），定出“书面硬 / 中性 / 偏口语”三档
2. 偏口语的段落：指出命中哪一测，给改写方向，不给定案
3. 引语、患者或受访者原话、术语、体裁要求的口语，单列进“待确认”，不动
4. 不改事实、数字、结论；不动结构，只标表达

输出：段位清单 + 改写方向 + 待确认清单
```

## 反模式

- 不要做成一对一词表——口语感在句式里，套表会改坏好句子
- 不要见到口语词就改——先定场合，工作稿和纪要里的口语是正常的
- 不要自动替换——这一关只做识别与标记，改不改由人拍
- 不要把引语、访谈原话、患者主诉当口语改掉，那是素材不是表达
- 不要越界到“去 AI 味”——翻译腔、模板句找 `gh-humanizer-zh` / `gh-no-ai-slop`；这一关只管“像不像说话”
- 不要跳过正则层只让 LLM 判——零散的“呗”“啦”人眼和 LLM 都容易漏，脚本抓得准
