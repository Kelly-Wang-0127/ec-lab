# 对外视图过滤

**核心规则：任何对外交付物在定稿前都过一遍这一关——把只有内部才需要看的内容清掉，只留读者该看到的部分；有人讲的载体，能被口述的一律不上版面，可删可不删的压成无语气的客观短语做补充，而不是留着一整句；补充是给讲者的提示点，不是印在页面上的结论。只做减法，不动事实、不动结论、不动数字。**

## 这一关治什么

写作时，过程信息和成品内容混在同一个文件里：改了几版、哪条被评审质疑过、哪个数字是暂定的。这些对作者有用，对读者全是噪音。清不掉，读者看到的是“我们改主意了”“这条对应意见 R11”，而不是“这个方案是什么”。

它治两类病：

- **过程混进成品**：版本史、评审编号、调试残留、给作者自己的待办
- **话太多**：页面上写着讲者会说的台词、读者不会带走的口号、谁都懂的自明铺垫

它和“去 AI 味”是两件事，两关都要过：

| | 去 AI 味（gh-humanizer-zh / gh-no-ai-slop） | 本技能 |
|---|---|---|
| 问的问题 | 这句像不像 AI 写的 | 这句该不该出现在给这个读者的版本里 |
| 层面 | 表达层（语言） | 读者层（内容）+ 表达层（口语） |
| 典型对象 | 翻译腔、模板句、空泛大词 | 版本记录、评审编号、调试残留 |
| 为什么单独需要 | 语言干净不等于读者对 | 语言再干净，把工作稿内容交出去照样是错的 |

**顺序固定：先本技能（删内容），再去 AI 味（润色剩下的语言）。** 先润色等于给马上要删的段落做无用功。反过来说，本技能删完的页面通常也没什么语言可润了——本来就没几句。

## 什么时候跑

- 任何对外交付物定稿前：交给评委、客户、外部单位、公开渠道、上级单位
- 触发词：对外交付、交付前检查、清内部痕迹、定稿前过一遍、给外部看的版本、口语识别、口语降档、书面语
- **不要**在写作过程中跑。写作时人需要过程信息（改到第几版、哪里被质疑过）；过早清掉等于丢掉工作记忆。它只属于最后一步。
- **要和口头配合的载体（授课 PPT、路演页、答辩页、演示页）必须走到第三轮**：第二轮抓错配，第三轮删话多、并把可删可不删的压成无语气的客观补充（只给事实骨架，展开交给讲者）。这类交付物最容易把作者视角和口播台词带出去。

## 第一步（必做，不可跳）：确认读者、载体与例外

1. **读者是谁**：评委 / 客户 / 公开读者 / 上级单位 / 学生听众
2. **载体是什么**：文档还是前端。两套清单不同，同一份交付物两者都有时都要查
3. **这个载体有没有人讲**：没人讲（独读型）/ 有人讲（讲伴型）/ 有的讲有的不讲（混合型）。这一条决定第三轮的阈值，先定下来
4. **例外先标出来，这些一律不动**：
   - 模板或规范明确要求的栏目
   - 法务、合规、伦理必需的免责声明（若多处重复，保留一处，多余的位置改到脚注）
   - 附录、脚注、参考文献、作者信息
   - 拿不准的一律不删，进“待确认”清单交回作者

## 先分清场合：文档和 PPT，抓的不是一回事

同一份活儿，两类载体的**主要矛盾**不同，别用同一把劲儿。第一步定了档，这一步就按档走：

| | 文档（独读型：报告、方案、说明、申报材料） | PPT（讲伴型：授课、路演、答辩页面） |
|---|---|---|
| 读者 | 没人讲，自己读；信息必须自足 | 有讲者现场讲；页面只留听众要带走的 |
| 主要问题 | 话是“关于内容的话”——元叙述、版本史、评审痕迹、自加栏目 | 话是“讲者该说的话”——整段讲稿、口令、铺垫、口号 |
| 主要动作 | **清元叙述**：自指表述改成对读者的直接陈述，该交代的一处说明白 | **极致减法**：整段拆开，能被口述的不上版面，可留可不留的压成无语气的客观短语 |
| 反着来的后果 | 拿 PPT 的阈值删文档，读者会读不懂 | 拿文档的阈值留 PPT，页面上印的是讲稿 |
| 走哪几轮 | 第一轮（载体 A 清单）+ 第二轮 | 三轮全走 |

PPT 和文档是两端的典型。带附录的汇报、自学课件这类**混合型**，在同一份里分别处理：讲的部分按 PPT 走，读者自己看的部分按文档走。

## 四条判据

不靠感觉删，靠这四条：

| 判据 | 怎么问 | 结论 |
|---|---|---|
| 读者测试 | 这句是写给“看结果的人”，还是写给“看过程的人” | 后者删 |
| 删除测试 | 遮住这段，目标读者的理解是否受影响 | 不受影响就删 |
| 自指测试 | 主语是不是“本文 / 本稿 / 本节 / 本页 / 本章” | 是，单独审一遍 |
| 重复测试 | 同一论断在别处出现过吗 | 只留最早或最完整的一处 |

## 元叙述：三轮共同的线索

三轮抓的东西看着不一样，指向的是同一件事：**元叙述**——不陈述对象本身，而是对对象做加工的话。

一条问句就能判：

> 这句是在讲**那件事本身**，还是在讲**该怎么看 / 怎么用那件事**？

后者就是元叙述。它有三种长相：

| 型 | 特征 | 常见样子 | 在哪一轮处理 |
|---|---|---|---|
| 自指型 | 主语是这份交付物自己（本页 / 本节 / 本稿 / 本章） | “本页用于展示……”“本节说明……”“本稿不给出……” | 第一轮：载体 A 第 3 类、载体 B 第 1 类 |
| 态度型 | 不出现“本”字，但对内容做解释 / 评价 / 纠偏 / 指导 / 包装 | “关键不是……而是……”“更容易”“试试这样”“一句话记住：……” | 第三轮：去语气、五种带语气写法、六种“话多” |
| 角色 / 流程型 | 讲的是这件事该怎么说、怎么排、交给谁，不是内容本身 | 印在页面上的讲稿、给讲者的口令、导航提示（“详见下页”） | 第二轮：按块过意图（角色 / 载体测试） |

还有一类纯元数据：版本史（“本稿 v03 相较 v02 精简了两页”）、评审编号（“（对应 P4-修订）”）、制作约定（“本页模板可套用到其他科普主题”）。讲的是这份交付物的来历和用法，同样归第二轮。

**为什么值得单独拎出来**：三轮各自记症状会漏；记住“元叙述”这一个上位概念，遇到没见过的写法也能当场判——只要它在讲“怎么看 / 怎么用”，不在讲“那件事”，就该被处理。处理方式看载体：讲伴型剥掉态度层降级成补充，独读型改成对读者的直接陈述。

## 载体 A：文档（报告、方案、说明、申报材料）

| # | 痕迹 | 命中样子 | 处理 |
|---|---|---|---|
| 1 | 稿件版本史 | “v01 稿曾用……v03 予以更正”“相对 v02 最重要的变化” | 删历史，留结论 |
| 2 | 评审编号 | “（对应 R11）”“（对应反方#7）”“（对应工程#8、C6）” | 全删；编号只属于内部评审表 |
| 3 | 自指元叙述（元叙述·自指型） | “本节说明……”“本稿不给出……”“本章要点：……” | 按判据删；确有必要交代的，改成对读者的直接陈述 |
| 4 | 重复的边界声明 | 摘要已交代过，正文各章再声明一遍 | 只留一处，删其余 |
| 5 | 立场说明段 | “关于……的立场：v02 稿曾……” | **改写而非删除**，见下方示例 |
| 6 | markdown 残留 | 行内 `**加粗**`、行首 `·` `◦` `- ` | 清标记；该成段的成段，该成表的成表（整篇结构见下方“大篇 markdown”） |
| 7 | 非正文字体粗体 | 正文体里冒出加粗强调 | 去掉加粗，强调靠句序而非字体 |
| 8 | 章末要点复述 | 与摘要、正文三处重复的“本章要点” | 删除（默认不留；确需保留时压成一句） |
| 9 | 自加的说明性栏目 | 非模板要求的“作品名释义”“作品速览”“术语说明” | 先核模板，模板没要求就删 |
| 10 | 直角引号 | `「……」` `『……』` | 换成全角弯引号“……”；直角引号是日式与港台排版习惯，大陆对外交付统一用弯引号 |

### 改法示范：不是删光，是换视角

原文：

> 关于“原理独特性”的立场：v02 稿曾把“认知效能可观测化”列为原理层面的创新。经复核，这一表述超出了本稿能够支撑的范围……v03 将该要素下调为设计要素。

出清后：

> 本方案的创新点按上表四项申领。认知效能可观测化列为设计要素，不申领原理层面的创新：其方法效度尚未标定（3.2、3.3），不足以支撑原理级主张。

差别：评委读到的从“我们改过主意”变成“这条边界在哪”。方案立场保住了，改稿过程消失了。

### 大篇 markdown：先问，再动

载体 A 里如果 markdown 结构占了主体（大量标题层级、项目符号、加粗强调、表格），**不要顺手全平掉，先问一句**：

> 这份要不要去掉 markdown，改成自然语言段落？

因为该用什么形态取决于**交付渠道**，不取决于内容：内部审阅、网页、说明文档里，markdown 结构正好；正式报告、申报材料、Word 交付物里，往往必须成段自然语言。替读者决定会做错，所以这一条是**问**，不是做。

确认要去之后再动手：

- 标题层级 → 按从属关系拆成段落，或用一句话领起
- 项目符号 → 能并列成句的写成句子；确实是清单的保留编号
- 加粗强调 → 去掉，强调靠句序（同第 7 类）
- 表格 → 数据、参数、对照保留；叙述性的改成文字
- 一个 markdown 块通常对应自然语言里的一个段落，别把一个块拆成好几段

**不在范围里的**：表格里的数据、步骤编号、参数清单——这些是该留的结构，不是要去掉的 markdown。

## 载体 B：前端（网页、HTML 页面、应用界面）

| # | 痕迹 | 命中样子 | 处理 |
|---|---|---|---|
| 1 | 元叙述文案（元叙述·自指型） | “本页用于展示……”“本页支持以下功能” | 删。页面用内容说明自己 |
| 2 | 未完成功能入口 | 点了弹“功能待开发”的按钮、开关、菜单项 | 删。没做完的功能不进交付物 |
| 3 | 调试面板与开发开关 | “调试面板”“仅开发时使用”的开关 | 删 |
| 4 | 对内注释 | 讲实现方式、给自己看的注释（`<!-- 之后可能换成动态标题 -->`） | 删 |
| 5 | TODO / FIXME | `// TODO: 接入真实接口` | 删 |
| 6 | 调试输出 | `console.log(...)`、`debugger` | 删 |
| 7 | 页脚元信息 | “本页面为演示版本，内容可能随时调整” | 删 |
| 8 | 占位措辞 | “示例数据”“占位”“Lorem” | 换成真实内容；换不了就删整块 |
| 9 | emoji 当图标 | `🌟📋🧭` 充当功能图标 | 转 `ec-no-emoji-icons` 处理 |
| 10 | 直角引号 | 页面上出现`「……」` `『……』` | 换成全角弯引号“……” |

## 第二轮：按块过意图（专治清单之外的冗余）

第一轮是**逐条**过：四条判据 + 上面两类清单，快，但只覆盖见过的症状。定稿前再走第二轮，换成**按块**过：一块一块问“这块是干什么用的”，把清单抓不到的东西也揪出来。

之所以会漏，是因为**载体一换，错配就来了**。PPT 是拿去讲的、页面是给人演示的、图表是配合口述的——内容一旦按作者视角堆进去，就会混进本该由**别的角色**或**别的渠道**承载的东西：讲稿、口令、导航提示、写作待办。这些不属于任何一类已知痕迹，但它们确实没用。

### 三步走

1. **切块**：按章节 / 页面 / 板块 / 区块切开，一块一块来，不跳块
2. **先说意图**：这块要表达什么？一句话说得出来吗
   - 说得出来 → 进入第 3 步
   - 说不出来 → 整块可疑：先问它为什么在，再定留、并还是删
3. **块内逐条过三道测试**

| 测试 | 怎么问 | 命中就处理 |
|---|---|---|
| 角色测试 | 这条是给**最终读者**的，还是给**中间角色**的（讲者 / 作者 / 协作者 / 机器） | 给中间角色的：删，或搬到它该在的地方 |
| 载体测试 | 这条信息该由**这个载体**承载吗（页面上该是给听众看的，还是该由讲者口头说的） | 错配就删 |
| 增量测试 | 这条给了读者新信息吗，还是别处已有、只是换个说法 | 没增量就删 |

### 典型错配（都很常见）

| 场景 | 混进来的东西 | 为什么该删 |
|---|---|---|
| PPT 是拿去讲的 | 整段讲稿（“讲稿：先举我排队三个月的例子”）、给讲者的口令（“停两秒再翻页”） | 讲稿由讲者说、口令给讲者看，听众都不需要 |
| 页面是给人按顺序看的 | “本节结论见下页”“详见附录”这类导航提示 | 读者会自己往下看，不需要被告知怎么读 |
| 图表是配合口述的 | 图上又写了一遍口述要讲的结论 | 讲的时候会说，图上留数据就够 |
| 方案是给客户看的 | 作者给自己留的取舍笔记（“这段可以再展开”） | 那是写作待办，不是给客户的内容 |

### 边界：这一轮不是“我觉得没用就删”

- 每条命中都要能指着三道测试里的**具体一道**说清理由；说不清的一律进“待确认”，不删
- 删的边界和第一轮一样：不动事实、数字、结论、署名和日期
- 别把该由载体承载的东西当冗余删了——图上该留的数据、页面该留的结论，是内容不是废话；要删的是“讲的时候会说”的那份重复
- 这一轮删多少由测试决定，不预设少。它确实是在补漏网，但漏网的有多少就删多少

## 第三轮：极致减法（按载体定阈值）

前两轮抓的是“不该在这的东西”；这一轮抓“位置没错、但没必要的东西”。

一句话：**有人讲的载体，能被口述的，就不上版面。**

### 先给载体定档

同一句话，在没人讲的文档里必须留，在有人讲的页面上就该删——差别不在内容，在**谁负责说**。

| 档 | 典型载体 | 谁在讲 | 阈值 |
|---|---|---|---|
| 独读型 | 报告、说明书、申报材料、给外部审阅的文档 | 没人讲，读者自己看 | 信息必须自足：来龙去脉、判断依据、口径都得在。**这一轮不适用** |
| 讲伴型 | 授课 PPT、路演页、答辩页、演示页 | 讲者现场讲 | 极致减法：只留读者要带走的 |
| 混合型 | 带附录的汇报、自学课件 | 有的讲有的自己看 | 按块分别定档，讲的部分按讲伴型走 |

### 留存测试（第四道）

> 遮住这一句，读者**带走**的信息少了吗？

- 少了 → 留
- 没少 → 别急着删，先看它有没有带补充信息，再定“删”还是“降级”
- 降级不是“把句子改短”，是“把句子降成客观事实”：只留事实骨架，态度、评价、展开全归讲者

### 没少的别一刀切：分三档处理

“讲者会说”不等于“一点信息都没有”。很多句子是**可以删、也可以不删**的——它确实带着一条有用的补充（作用、原理、时机、注意），只是一句完整的话摆在正文位置上，占得多、也像正文。

这类不删，也不留整句，**降级成补充**：

| 档 | 什么情况 | 处理 |
|---|---|---|
| 删 | 纯粹是话：导语、口号、过渡、共情铺垫、自明铺垫 | 整条去掉 |
| 降级 | 可删可不删：句子里还带着一条补充信息 | 摘出补充，压成**无语气的客观短语**，挂到主体内容下面——去口语，更要去语气 |
| 留 | 遮住它读者带走的信息就少了：做法、参数、步骤、判断标准、结论、边界 | 原样留，该是完整句子就完整句子 |

### 降级怎么做（三步）

1. **摘出实义**：这句话里真正带信息的是哪几个词
2. **压成客观事实**（见下）：去掉主语代词（“它”“这”）、去掉口语状语（“……的那几分钟” → “……时”）、去掉“常用于”“其实”“往往”这类连接词，**再把语气一并去掉**
3. **挂到主体下**：不再是独立段落，改成主体内容（做法 / 步骤 / 结论）下方的附属小字，前面加一个性质标签

### 第 2 步要做到底：去语气

去口语只是第一刀。改短了仍然带语气的句子，是“被轻声念出来的台词”，读者读到的还是说话人的态度。**去语气 = 剥掉元叙述的态度层**：把“对内容做加工”的那层去掉，只留对象层的事实骨架；**去语气之后，它才变成给讲者的提示点**。

下面五种“带语气”的写法，都是**元叙述·态度型**的常见长相：

| 类型 | 样子 | 问题 |
|---|---|---|
| 强调 / 纠偏句 | “关键不是比例，是呼气比吸气长”“真正要练的是……” | 说话人在纠正读者，页面不该有课堂口吻 |
| 评价副词 | “更容易”“不那么冲”“基本”“往往”“多半” | 说话人在下判断，事实被态度包了一层 |
| 情绪形容词 | “快撑不住”“最顺手的”“全都练不成” | 口语化主观词，换成中性表述才立得住 |
| 祈使 / 建议 | “挑一个最顺手的”“试试”“别……” | 页面在指使人；建议该由讲者现场给 |
| 心理解释 | “更容易拉开距离，判断也没那么冲” | 解释是讲者的活；页面只给事实骨架 |

改法：**降成名词短语、关系式或条件式，不带说话人姿态。**

| 带语气（仍不合格） | 无语气（合格） |
|---|---|
| 关键不是比例，是呼气比吸气长 | 呼气长度 ＞ 吸气长度 |
| 它把注意力从反刍里拽回当下 | 中断反刍，注意力回到当下 |
| 用“你”或自己的名字称呼自己，判断也没那么冲 | 第三人称自称增大心理距离 |
| 等“有动力了再动”基本等不到 | 行动先于动力 |
| 挑一个最顺手的，练两周，再看有没有用 | 选定一项，两周后评估 |

能写成符号或关系式就用符号（`呼气长度 ＞ 吸气长度`）；能用名词短语就别写成句子（`行动先于动力` 优于“动力往往跟在行动后面”）。

**自检**：读这条补充，能不能读出“说话的人”？读得出态度——是提醒、是纠正、还是建议——就还没降到位。合格的补充只给事实骨架：读者看清事实是什么，为什么要这么做、该怎么用，全部留给讲者展开。

改法示范：

> 它把注意力从反刍里拽回当下，常用于情绪冲顶、快撑不住的那几分钟。

降级后：

> 作用　中断反刍，注意力回到当下
> 时机　情绪冲顶、濒临失控时

“它”没了，“那几分钟”收到“时”，“拽回”“快撑不住”换成中性表述——一句完整的话变成两条挂在主体下面的短标签，且读不出说话人的态度。

### 补充常用标签

| 标签 | 承载什么 | 例 |
|---|---|---|
| 作用 | 这个东西干什么用 | 中断反刍，注意力回到当下 |
| 原理 | 为什么有效 | 呼气延长时心率下降 / 行动先于动力 |
| 时机 | 什么时候用 | 情绪冲顶、濒临失控时 |
| 注意 | 最容易做错的地方 | 呼气长度 ＞ 吸气长度 |
| 做法 | 怎么执行、什么节奏 | 选定一项，两周后评估 |
| 条件 | 适用范围与前提 | 需要能安静坐下来的地方 |
| 目标 | 做到什么程度 | 唤醒度回到可用区间：能思考、能选择、能表达 |

每个标签后面的内容同样要无语气：写事实，不写劝告。

### 六种高发的“话多”（元叙述·包装型，一律进“删”档）

| 类型 | 样子 | 为什么该删 |
|---|---|---|
| 导语 / 宣传语 | “五个能立刻上手的练习，帮你稳住自己” | 讲者一张口就是这句，页面留标题就够 |
| 口号式收束 | “一句话记住：……”“记住这句就够了” | 包装本身是口播动作；结论若正文已有，整条删 |
| 过渡句 | “接下来我们看……”“在讲这个之前” | 那是翻页动作，不是内容 |
| 共情铺垫 | “这很正常，你不是一个人” | 讲者现场给才有分量，印出来只剩套话 |
| 自明铺垫 | “情绪对人有影响”这类谁都知道的话 | 不带来新信息，也不改变理解 |
| 结论重述 | 换个说法把上一段又说一遍 | 只留一处，通常留最完整的那处 |

### 这些一律不许删

删的是“话”，不是“信息”。下面几类一个都不能少：

| 类别 | 例（以授课页为例） |
|---|---|
| 做法与参数 | 吸气 4 秒、停 7 秒、呼气 8 秒 |
| 步骤与顺序 | 看见 5 样、摸到 4 样、听到 3 种…… |
| 判断标准 | 持续两周以上；已经影响睡眠、进食、工作或学业 |
| 边界与警示 | 不替代评估和诊疗；出现伤害自己的念头要去就诊 |
| 本交付物特有的定义 | 读者需要记住的概念、口径、缩写 |

### 边界

- **删之前先确认讲者补得上**：这句话我能在台上自然地说出来吗？说不出来，它就不是话多，是信息缺口
- **降级不是软性保留**：压不出实义的，说明它本来就是空话，直接删；降级只留给真带补充信息的句子
- **降级不只是去口语，更要无语气**：改短了还带态度，就还是“一句被念出来的台词”。补充要写成客观陈述或关系式，讲者的活是把它讲开，不是照着念
- 补充是附属，不能反过来占主导：主体内容（做法、步骤、结论）不能被补充挤掉；一条主体底下最多挂两三条，再多就该按正文处理了
- 只对讲伴型用。独读型走了这一轮，会删出一个读不懂的东西；降级同样只对讲伴型开放，没人讲的时候该成句的成句
- 拿不准的进“待确认”

## 口语识别与降档

前三轮治“不该在的内容”，这一层治“像在说话的表达”。它不去管翻译腔和模板句——那是 `gh-humanizer-zh` / `gh-no-ai-slop` 的活；它也不做结构减法——那是前三轮。它只回答一件事：**这句话读起来像写出来的，还是像说出来的。**

| | 前三轮（读者层） | 本层（表达层·口语识别） |
|---|---|---|
| 治什么 | 内容该不该在这 | 表达像不像写文章 |
| 动作 | 删内容、改视角、把话降级成客观补充 | 标记 + 给方向，不动结构、不自动替换 |
| 适用载体 | 讲伴型走满三轮，独读型走前两轮 | 所有载体，阈值按场合定 |

### 为什么不做“一对一词表”

口语感大多藏在**句式**里，不在词上。比如“关键不是比例，是呼气比吸气长”——一个口语词都没有，整句仍是课堂口吻。查词表抓不到它，因为它没有可疑的词，只有可疑的**姿态**。所以做法是查特征，不是查词。

| 只查词会漏的 | 为什么 |
|---|---|
| 关键不是……是…… | 词都书面，问题在纠正读者的姿态 |
| 一句话记住：…… | 口令式包装，词本身没错 |
| 你会发现…… | 把读者体验写进正文，是口播动作 |
| 反正…… | 口语衔接，无实义，但看着像随便聊 |
| 搞明白 / 弄一下 | 单字口语动词，书面用“厘清 / 处理” |

### 两层怎么分工

| 层 | 做什么 | 谁执行 |
|---|---|---|
| 正则层 | 抓有固定形态的特征，出文件 / 行号 / 类别 / 档位清单 | `scripts/scan_colloquial.py` |
| LLM 层 | 逐段判正式档位、给改写方向、标出该留的 | 加载本技能的 agent |

两层都要跑。只跑脚本会漏掉**没见过的句式变体**（正则只认已知模板）；只靠 LLM 会漏掉零散的“呗”“啦”。特征清单、三测判据与提示词模板见 `references/口语识别.md`。

### 先定场合，再定阈值

同一句话，独读型文档里必须留，讲伴型页面上就该动。先看载体，不因为见到一个口语词就动。

| 载体 | 阈值 |
|---|---|
| 独读型（报告 / 方案 / 申报材料） | 高、中档都看；低档仅提示，多半可留 |
| 讲伴型（授课 / 路演 / 答辩页面） | 三档都看，中档在这类载体上通常也该动 |
| 工作稿、会议纪要、内部沟通 | 全留，这一层不适用 |
| 文学、访谈、科普 | 看体裁；体裁本身要的口语就留 |

### 三类一律不动

- 引语与访谈原话
- 患者或受访者的主诉、自述
- 体裁本身要求的口语（对话体、科普的亲切感）

### 只标记，不替换

脚本和人都不自动改字。每一条都要能说清：命中哪类特征、在哪一档、往哪个方向改。改不改、改到哪一档，由作者按场合定。把口语识别做成一键替换，等于把作者的语感一起换掉。

## 说清楚：表达层的底线

口语识别管“太像说话”，这一层管“太像机器”和“说不明白”。它不管文采，只管一件事：**读者第一次读到，能不能不查来源就懂。**

### 三条一律适用（不分载体）

| 条 | 命中样子 | 处理 |
|---|---|---|
| 不造压缩词 | 多词说法压成的短词、自造的概括标签（“论证质量线”“行会共识”） | 展开成完整说法，或首次出现时紧跟一个具体实例再沿用 |
| 歧义词写清主体与客体 | 一句话能被读成两种意思（谁对谁、谁影响谁不明确） | 把主体和客体写出来 |
| 中文里非专业名词不用英文 | 有通用中文说法却写成英文（imprinting 形状、baseline） | 用中文；只有没有通行译法的技术术语（API、token、commit）保留英文。外文名词按意思选最贴切的译法，不逐字直译成生造词 |

**不造压缩词的检验**：拿掉上下文，领域新人首次读到能不能不查来源就懂。不能的，展开成完整说法，或首次出现时配一个具体实例。

### 成句程度按档定

| 档 | 要求 |
|---|---|
| 独读型 | **正文成句**：每句有完整主谓，不用名词短语堆砌代替句子。**推理链自足**：理解结论所必需的中间步骤不能省；结论之外的展开仍可省 |
| 讲伴型 | **反向**。页面上的补充本来就是短语、关系式或标签，不要求成句；中间步骤与展开交给讲者口述，页面上不写 |
| 前端 | 同讲伴型。界面文案是标签，不是句子 |

**范围**：这一层只管**成句的说理文字**。表格数据、参数清单、步骤编号、页面标签、挂到主体下的补充条，都不属于“句子”，不受成句要求约束——讲伴型和前端硬展开成句，反而违背第三轮的降级口径。

## 执行顺序

按第一步定的档走：文档重清元叙述，PPT 重极致减法（见“先分清场合”）。

1. **读者层·第一轮**：四条判据 + 两类清单，逐条抓已知痕迹
2. **读者层·第二轮**：按块过意图，抓清单覆盖不到的错配（PPT 讲稿、演示口令、导航提示这类）
3. **读者层·第三轮**：按载体定档做极致减法，抓“位置没错但没必要”的话（本质是元叙述的态度型）——该删的删，可删可不删的降级成**无语气的客观补充**（只对讲伴型）
4. **表达层·排版**：清 markdown 残留、非标体粗体、直角引号统一成全角弯引号；整篇 markdown 结构占主体时**先问要不要平化**（见“大篇 markdown”）
5. **表达层·口语识别与降档**：先跑 `scripts/scan_colloquial.py` 出清单，再按 `references/口语识别.md` 的 LLM 层逐段过三测（人称 / 解释 / 口播），定档位、给方向；只标记不替换
6. **表达层·说清楚**：三条底线（不造压缩词、歧义词写清主体与客体、中文里非专业名词不用英文）不分载体都过；成句程度按第一步定的档走（见“说清楚”）
7. **语言润色**：交给 `gh-humanizer-zh` / `gh-no-ai-slop`
8. **复核**：确认事实、数字、结论一个都没被动过；确认例外清单里的东西还在

## 输出三样（缺一不算做完）

1. **清理后的成品**
2. **“清掉了什么”清单**：按载体分组，逐条列原名、处理方式（删 / 降级 / 留）与理由——第一轮写命中的判据 / 痕迹类别，第二轮写命中的测试与这块的意图，第三轮写载体档与留存测试的结论，降级的条目要一并给出压好的短语（须是无语气的客观陈述），供作者复核；表达层动过的地方一并列入，写清命中哪一测或哪类特征、往哪个方向改
3. **“待确认”清单**：拿不准的条目交回作者定，不擅自删

## 反模式

- 不要把这一关变成重写。它只做减法，最多做视角转换
- 不要动事实、数字、结论、署名和日期
- 不要为了“看起来干净”把必要的边界声明也删了——该交代的边界属于方案内容
- 不要把模板栏目当自加栏目删（删前先核模板原件）
- 不要在写作过程中跑，会丢工作记忆
- 第二轮不要靠“感觉没用”下刀：给不出测试理由的，进“待确认”
- 第三轮不要对着独读型载体用：没人讲的地方删掉铺垫和交代，会删出一份读不懂的东西
- 第三轮不要一刀切：讲者会说不等于信息为零，可删可不删的降级成补充，别把带信息的句子整句砍掉
- 第三轮别把降级做成“缩短版原句”：去口语只到一半，去语气才算到位。带着强调、评价、建议口吻的句子，读者读到的是态度，不是事实
- 不要把口语识别做成一词换一表：口语感多在句式里，查词抓不到“关键不是……是……”这类
- 不要自动替换口语痕迹：只标记、给定档与方向，改不改由作者按场合定
- 不要把“说清楚”做成把所有短语展开成句子：讲伴型和前端本来就该是短语、关系式、标签，展开反而违背第三轮的降级口径。成句要求只管成句的说理文字
- 不要为了“不造词”把作者已在用的词改掉：作者自己提出并沿用其含义的比喻、缩略语、术语照用；管的是新造的词，不是他的词

## 与其他技能的分工

| 现象 | 找谁 |
|---|---|
| 语言像 AI 写的、翻译腔、模板句 | `gh-humanizer-zh`、`gh-no-ai-slop` |
| 界面用 emoji 当图标 | `ec-no-emoji-icons` |
| 内容打斗、逻辑漏洞、事实错误 | `ec-blind-review` |
| 只该内部看的内容泄漏到成品、页面上话太多 | **本技能**（读者层三轮） |
| 像说话不像写文章、口语词与语气残留 | **本技能**（表达层·口语识别与降档） |
| 说法含混、自造压缩词、中英混用、术语不展开 | **本技能**（表达层·说清楚） |

## 配套脚本

```bash
python scripts/scan_internal_traces.py <文件或目录>            # 第一轮已知痕迹，文本报告
python scripts/scan_internal_traces.py <文件或目录> --format json
python scripts/scan_colloquial.py <文件或目录>                 # 口语痕迹，独读型口径（默认）
python scripts/scan_colloquial.py <文件或目录> --register ppt  # 讲伴型口径
python scripts/scan_colloquial.py <文件或目录> --min-level mid # 只看中档及以上
python scripts/scan_colloquial.py <文件或目录> --format json
```

支持 `.md` / `.txt` / `.html` / `.htm` / `.docx`（自动解包读正文）与目录递归。
脚本覆盖的是**第一轮的已知痕迹**，给的是文件、行号、命中类别与原文片段；第二轮、第三轮的判断抓不到的东西脚本不管，删不删都由判据和测试决定。
